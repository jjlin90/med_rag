## 代码修复

1. `audit_repository.py`原来只使用`git ls-files`，新文档断链、来源脚本及凭据混入可能漏扫。现在合并已跟踪与未跟踪且未忽略的文件清单，检查本地链接/锚点、禁入产物及本地凭据值；分别报告tracked/untracked/worktree计数，临时产物仍排除，不需要先暂存文件。增加output/pdf、tmp、独立MinerU环境忽略探针，以及新源码/文档/测试保留探针。凭据值不输出。
2. 静态审计原本已经覆盖项目目录中的新Python文件与项目Markdown，现在报告明确范围；仓库审计还包括模型README。因此两工具Markdown总数不同并不代表漏扫，要对照范围与文件清单。
3. `normalize_markdown`先恢复代码，再压缩连续空行，会改写代码原文。改为先清理非代码部分，再恢复代码。
4. `DataCleaner`随后仍对Markdown全体执行字符清理、行尾空格删除和空行压缩。新增保护包装，只处理代码外的正文，保留行内/围栏代码的原始空行、行尾空格与字符；PDF/TXT等原路径保持原行为。
