## 修复的评测问题

1. `eval_f_ar_paired.py` 部分答案从文件复用、其余在线生成时，旧代码按缺失列表位置回写，会把新答案放到其他问题。现保留原题索引，并用部分缓存的三题联调回归验证题目与答案对应。
2. 旧自定义裁判将网络失败、JSON 解析失败当成零分，并把越界值裁剪到 0～1。现严格解析完整 JSON，拒绝布尔值、非有限值、越界值及截断响应；失败保留 null，真实零分保留。
3. F/AR 两侧分别取均值或缺项补零，会使用不同分母。现仅对同题、两侧 F/AR 都有效的完整配对计算双方均值与差值，保留失败题明细；无完整配对时汇总为 null。
4. 旧脚本把自定义裁判 F/AR 与硬编码的历史 CP/CR 拼接成综合分。现只发布本次实际评测的指标，标明正式 Ragas 或自定义裁判引擎，不拼接跨口径分数。
5. 答案对照入口检查冻结上下文和已记录的生成模型，阻止用不同证据评价同一个答案对照，以及已知生成模型与裁判相同的正式比较。Ragas 配对入口拒绝自动回退到自定义裁判。
6. 裁判临时环境变量用 finally 恢复，异常也不会污染之后的模型配置。CSV 对缺失评分输出空单元格，并创建嵌套输出目录。
7. Ragas 逐题结果保留原始浮点精度，汇总显示时再舍入。CP 定义修正为上下文排序精确度，不能替代“上下文相关性”目标。
8. 两个自定义裁判脚本 `eval_f_ar_direct.py` 与 `eval_f_ar_single_judge_210.py` 原先只把前三条上下文放入评分提示。现使用全部传入上下文，避免第四条及之后的证据被遗漏；已有回归验证第四条上下文进入提示。
