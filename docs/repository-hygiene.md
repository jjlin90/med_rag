### 从源码工作区复现当前检查

在克隆后、含Git索引的源码根目录运行[仓库审计脚本](../scripts/audit_repository.py)：

```bash
python scripts/audit_repository.py
# 可选：把本次结果保存到忽略目录
python scripts/audit_repository.py --output artifacts/repository_audit.json
# 发布前额外要求：已跟踪文档的本地文件链接目标也已纳入Git
python scripts/audit_repository.py --require-tracked-links
# CI要求实际完成凭据比对时使用；根目录.env须有至少1个符合条件的凭据字面值
python scripts/audit_repository.py --require-local-credentials
```

脚本核查已跟踪与未跟踪且未忽略的工作区文件：Markdown本地链接与锚点、本地凭据值及禁入产物。另检查忽略/保留规则及被忽略规则覆盖的已跟踪文件，不需要先暂存新文件。报告分别记录tracked_files、untracked_files、worktree_files及总Markdown数；静态检查只扫描项目文档，仓库检查还包含模型README，范围字段明确说明两者区别。output/pdf、tmp及独立MinerU环境增加忽略探针，新增源码/文档/测试增加保留探针。每次实际路径探针数见报告的 `ignore_probes`，本地链接及锚点数见 `local_links_checked`；新增路径或文档链接后须重新检查，历史计数不代表后续版本。核心检查只需要Python标准库和Git，无GPU、Docker、数据库或模型接口调用；Git提供已跟踪及未忽略新文件清单，因此仅解压源码包时需用`--root`指向对应Git源码工作区。退出码0表示已执行检查通过，1表示发现问题，2表示检查无法完成。默认不修改文件，只有指定`--output`才写报告。

若根目录存在`.env`，使用项目依赖python-dotenv解析，其中名称包含API_KEY/PASSWORD/TOKEN/SECRET、长度至少8的非占位字面值在已跟踪及未跟踪且未忽略的工作区文件中逐字节比对；不展开变量引用，报告只给出命中文件与配置字段名，不输出凭据值。这是本地环境凭据值核查，范围不包含其他来源的未知密钥或历史提交。克隆后没有本地`.env`时明确标为`skipped_no_local_env`；如主动使用`--skip-local-credentials`则标为`skipped_by_option`，均不作为凭据扫描通过的证据。

文件存在与可随Git交付分别检查：`broken_links_or_anchors`报告缺文件/缺锚点，`untracked_link_targets`报告已跟踪Markdown链接到现存但未纳入Git索引的本地文件（包括被忽略的文件），或解析到仓库外的相对文件目标。`tracked_file_links_checked`记录后者检查的文件链接数；目录链接不纳入这项文件检查，网络链接沿用跳过规则。对仓库内文件，目标路径按Git索引清单精确匹配，效果相当于检查 `git ls-files --error-unmatch`；已暂存的新文件也算已跟踪，这不证明已经提交、推送或进入分发包。

2026-10-14后续修订：Windows盘符路径（如 `D:/...`）、本机绝对路径和本机 `file:///...` / `file://localhost/...` 文件链接现在检查存在性及锚点，并支持百分号编码的路径。已跟踪文档使用绝对本地链接时另记入 `nonportable_link_targets`，即使目标文件已纳入Git，也不能依赖另一个克隆者使用同一磁盘路径；发布时应改为仓库相对链接。发布门控要求未跟踪目标和不可移植目标两份清单都为空；普通工作区模式仍报告两份清单。

HTTP/HTTPS、mailto、data等其他协议及 `//host/...` 网络链接不访问，数量写入 `external_links_skipped`，本地审计通过不代表这些外部目标可用。远程主机的file URI、网络文件系统路径及不支持的file URI格式直接记录为检查问题并返回1，不静默跳过，也不尝试访问远程共享。Windows盘符路径在非Windows环境无法核验时同样报告问题。目录链接仍不做Git文件索引归属检查，但绝对目录链接会进入不可移植清单。

第四阶段修订：反斜杠相对路径（包括百分号编码的反斜杠）也进入 `nonportable_link_targets`，原因标为 `backslash in local path`；Windows上目标存在也不能据此证明GitHub/POSIX路径可用，仓库文档统一用正斜杠相对路径。

[静态审计](../scripts/audit_static.py)与仓库审计现在共用 `audit_document_links`，统一识别本地路径、file URI、编码、锚点、行内/围栏代码示例及不可移植路径。静态审计报告本地链接数、外部跳过数及不可移植清单，缺文件、缺锚点或不可移植目标均返回1。静态审计不读取Git索引；仓库审计的 `--require-tracked-links` 继续额外核对已跟踪文档的文件目标是否纳入Git。两者文档范围分别为项目文档与含模型README的工作区文档，链接总数可能不同，要按范围解读。

第五阶段明确可移植性范围：静态审计的 `portability_scope=all_scanned_markdown`，覆盖全部扫描到的项目Markdown，包括未跟踪草稿；仓库审计的 `portability_scope=tracked_markdown_only`，只对已跟踪文档执行可移植性与Git归属门控。未跟踪草稿在仓库审计中仍检查文件存在性与锚点，但暂不要求路径可移植；所以本地可打开的绝对草稿链接可能让静态审计返回1，而仓库发布门控仍返回0。草稿纳入Git后，绝对/反斜杠链接会被发布门控拒绝。这是声明的范围差异，共用解析实现不代表两个结果覆盖的文档和门控范围相同。

静态报告的 `broken_local_links` 与 `nonportable_link_targets` 统一用 `path` 表示来源文档，另列 `target` 和 `reason`；仓库报告继续用 `file` 表示来源文档。对照两种报告时按字段映射和范围比较，不能只比较链接总数。

静态审计的 `link_check_scope` 同时写明共享解析与可移植性范围，避免只读描述时误认为两工具约束同一批文档。问题条目映射采用复制后仅将 `file` 改名为 `path`，保留其余诊断字段，以免将来新增字段被截掉。

默认模式保留新文档的工作区检查行为，但仍输出未跟踪及不可移植目标清单。发布前使用 `--require-tracked-links`：任一清单非空时，`tracked_link_requirement_met`为false，返回1。未跟踪草稿链接到另一份未跟踪草稿仍检查存在性与锚点，纳入Git后才要求其文件目标也在索引中。默认模式返回0不能单独证明链接目标可随Git交付；发布门控与包内容检查须分别完成。

`--require-local-credentials`与跳过选项互斥：只有扫描状态为`checked_local_literal_values`且实际比对至少1个有效凭据值时，`credential_scan_requirement_met`才为true；没有本地.env或没有符合条件的值时返回1。默认模式仍允许无.env的克隆检查通过，并明确记录跳过状态。CI通过受保护的本地环境文件提供待核查值，文件按现有规则忽略。

禁入后缀同时覆盖`.bin/.onnx/.h5/.msgpack/.tflite`等权重或模型导出文件，和Git已跟踪但应忽略的文件检查互相补充；配置、分词器与说明资产继续保留。检查无法完成时返回2，并用安全错误分类区分根目录不可用、Git不可用/失败、缺少python-dotenv、文件编码/读取失败及报告写入失败；不回显原始异常中的文件内容或凭据值。
