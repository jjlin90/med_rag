# 工程修订与面试详解（精简口述版）

> 核对日期：2026-10-08。原有 27 道题和 6 个附加追问全部保留，答案可直接讲给面试官。工程行为已重新运行回归，本地数据与历史评分已复算；验收记录见 [本轮检查](review_20261008.md)。

完整项目链路见[学习与面试全解](med_rag_学习与面试全解.md)。讲工程问题时，按“现象→根因→处理→验证范围”展开；以下答案已按这个顺序组织，关键术语附中文释义。

## 一、当前端到端流程

**离线直接讲：** 我先独立执行 HTML（超文本标记语言）抽取，再加载、清洗和父子分块。父块上限 2000 字符、子块上限 400 字符、重叠 60 字符；保存分块后，用 BGE-M3 生成稠密和稀疏向量，再写入 Milvus。抽取不会由入库脚本自动执行，历史数据迁移也需要单独操作。

**在线直接讲：** API（应用程序接口）先查结果缓存，再尝试符合条件的 FAQ（常见问题）快通道。未命中才做通用/医疗意图分类；医疗问题选择策略，混合检索最多 16 个子块、取前 5 个回溯父块、用代表子块精排，最多 2 条上下文生成答案。正常空召回可尝试 L1 备用检索，服务故障进入 L2；默认无证据拒答，L2 不缓存。

## 二、修复专题与面试追问

### 问题 1：缓存已经用了哈希，为什么仍会答错？

旧实现先删除标点，再算 MD5（哈希摘要），所以 `1.5mg` 和 `15mg` 在计算哈希前已经相同。根因是预处理丢失语义，换哈希算法也无法补救。我改为只去首尾空白，保留小数点、符号和单位；问答缓存对结构化输入计算 SHA-256（哈希摘要），FAQ 仍用 MD5，两者都升级 v2 命名空间。

**追问：为什么要 v2？** 我用新命名空间隔离旧的错误条目，让旧缓存按 TTL（生存时间）自然过期，避免修复后继续命中旧答案。

### 问题 2：缓存键需要哪些维度？一定要包含 session_id 吗？

我按“哪些输入会改变答案”设计缓存键，加入问题、来源、策略和实际 history（历史消息）。`session_id`（会话标识）只定位记录：同一会话历史会变化，不同会话也可能提供相同历史。因此仅加会话 ID 不够。当前缓存保留完整请求历史，即使生成只取最近消息，也会更保守地隔离结果。

**追问：知识库更新怎么办？** 目前还没有把知识库、模型和 prompt（提示词）版本纳入失效机制；后续需要版本号或主动失效，解决更新后旧答案继续命中的问题。

### 问题 3：为什么缓存命中还要写会话？

缓存节省检索和生成，用户这一轮交互仍需记录。旧实现直接返回，刷新后会丢失这轮历史。我改为命中后也保存当前会话、问题和答案。已有模拟存储回归确认 API 发起了正确写入；真实 MySQL 故障下的持久化仍需联调验证。

### 问题 4：FAQ 的 0.85 能不能说成 85% 准确率？

不能。softmax（归一化指数函数）表示候选之间的相对分布，没有经过正确/错误标签校准。单候选即使匹配很弱也会得到 1。当前先拒绝最高 BM25（词项相关性排序算法）原始分不大于零的结果，再检查 0.85 阈值，修复了零匹配也能直答的漏洞。

**追问：正分就足够了吗？** 还不够。近邻疾病、否定和剂量差异也可能得到正分。我会用独立正负样本统计错误直答率与覆盖率，再标定绝对分、词项覆盖或验证条件。

### 问题 5：为什么有历史或 source_filter 时跳过 FAQ？

当前 FAQ 只匹配问题文本，不理解历史、不按来源过滤，也不会执行指定检索策略。直接返回可能违背请求约束，所以有历史、`source_filter`（来源过滤）或显式策略时，我让请求进入 RAG（检索增强生成）深通道。将来 FAQ 补齐来源元数据和上下文判断后，才能重新评估适用范围。

### 问题 6：为什么不能把检索异常当成空列表？

空结果表示正常没查到，异常表示服务故障；混在一起会影响降级和告警。我让 Milvus 和 Embedding（向量编码）异常向上传播，检索层写入 `status.error`（错误状态），再转成带级别和原因的检索结果。核心据此区分 `no_recall`（无召回）与 `retrieval_error`（检索错误）。

**追问：测试有没有真的连数据库？** 这组故障测试没有。它调用真实应用包装层，在 SDK（软件开发工具包）边界注入异常，验证错误向上传播和最终响应；网络与实际数据库另做联调。

### 问题 7：子查询一部分成功，为什么整体仍然拒答？

部分子问题检索故障时，剩余资料未必能覆盖原问题。旧合并逻辑可能隐藏降级，甚至缓存部分失败答案。当前任一路 error（错误）都升级整体 L2 并默认拒答；没有错误时取有产出分支的最高降级级别，L0+L1 标记 L1。正常空召回与服务故障仍分开处理。

**追问：能做部分回答吗？** 可以，但要明确哪些子问题未覆盖、证据对应关系、失败原因和缓存规则。当前没有完整的部分回答机制。

### 问题 8：为何重排失败也要对调用方可见？

重排决定生成器最终看哪些证据，失败后按原顺序返回会掩盖流程故障。我让缺模型、计算异常、分数数量不符、NaN（非数值）或无穷分数明确报错；核心返回 `reranker_unavailable`（重排不可用）的 L2 响应，不进行最终生成，也不缓存。重排后还检查空正文，避免用空证据生成。

### 问题 9：DOCX 加载为什么看起来没有报错却没有内容？

模块导入的 python-docx `Document` 被内部同名类覆盖，实际调用时参数不符，异常又被转为空结果。我把外部工厂改名 `DocxDocument`。已有回归真正创建临时 DOCX、写入包含 `1.5mg` 的正文，再加载核对内容，覆盖基本正文读取；复杂排版、表格和图片仍需验证。

### 问题 10：文本清洗为什么需要数值回归？

旧页码规则用 `re.search`（局部正则匹配），正文含 `120/80` 就可能整行删除；数字行也曾被误判为噪声。医疗数值被删后句子仍可能通顺，日志难以发现。我改用 `re.fullmatch`（整行正则匹配），取消无标签数值比值规则，保留数字和单字符，并测试该留的数值与该删的页码。

**追问：是否证明清洗完全无损？** 没有。重复行、表格和 HTML 结构仍需抽样对照原文，并统计数值与单位保留率。

### 问题 11：备用分块为什么也会影响数据正确性？

旧备用路径读错正文属性，按偏移计算 ID 在重叠时可能重复，标点截断后的步进还可能漏字。我适配 `content/page_content`（两种正文属性），用窗口序号及父 ID 命名，并采用覆盖全文的固定滑窗。回归检查字符覆盖、块长和 ID 唯一，配置也拒绝非法重叠值；备用结果不保证与主切分器完全相同。

### 问题 12：修复 chunk_type 就等于修复历史知识库吗？

不等于。代码、磁盘 JSON（结构化数据文件）和 Milvus 集合是三种状态。当前读取和入库按 `parent_id`（父块标识）恢复类型，查询联合检查 `chunk_type`（块类型）与父 ID，避免误标父块挤占候选。真正迁移还要备份、核对父子关系、写新集合并验收数量和召回；这些不会因改代码自动完成。

### 问题 13：向量化为什么不能失败一批就继续？

失败返回空数组时，`zip`（按最短序列配对）会静默丢记录，日志看似完成，知识库却缺一部分。我让推理异常抛出，并检查稠密、稀疏输出与输入数量一致；稀疏词项 ID 和权重统一为整数、浮点类型。断点恢复、部分写入处理和事务性重建仍需要另做设计。

### 问题 14：timestamp 为什么改成可选？

恢复历史只有问题和答案，前端重建为 role（角色）和 content（内容），没有 timestamp（时间戳）。原接口要求时间戳，刷新后续聊就触发 422（请求校验错误）。它不参与检索或提示语义，所以我改为可选；角色、非空内容和末尾用户消息仍严格校验。已有 HTTP（超文本传输协议）接口回归覆盖恢复消息不带时间戳的情况。

### 问题 15：为什么同秒历史要增加 id 排序？

多条记录可能在同一秒写入，仅按 timestamp（时间戳）排序不能稳定区分先后。我在读取和保留最近 5 轮的裁剪中统一加入 ID 降序，再反转成旧到新的历史。这解决同秒排序歧义；多进程、共享连接和事务并发仍需真实数据库测试。

### 问题 16：general 分支为什么需要单独提示词？

general（通用）不检索医学知识库，旧代码却复用“只能依据医学上下文”的 Grounding（基于证据作答约束）提示词，同时给空上下文，目标冲突。我为通用问题提供独立提示词，医学分支保持证据约束，生成失败标记 L2。医疗问题被错分到通用分支的风险，还要靠独立意图测试集验证。

### 问题 17：评测失败为什么不能记 0？

零分表示已经评出但质量差，超时或解析失败表示没有评出。混用会让基础设施故障拉低质量均值。我把缺项、解析失败、非有限和越界分数记为 null（缺失值），真实零分保留；均值只用有效评分，无有效值也返回 null，并报告有效数和完整率，便于识别缺失偏差。

### 问题 18：整列 NaN 为什么必须保留？

删掉全 NaN（非数值）列，会把“请求了但全失败”伪装成“没有评这项”，完整数也可能被高估。我保留已知指标列，失败值为 null（缺失值），有效数为 0，完整行按实际指标集合统计。整次 Ragas 异常可以显式走备用引擎；请求指标、返回指标和参考答案是否齐全仍需一并检查。

### 问题 19：为什么不能拿 fallback 的 CP 与 Ragas CP 混算？

fallback（备用裁判）用自定义提示词一次给分，正式 Ragas 有独立指标定义；名称相同不代表测量方式相同。我按 engine（评测引擎）区分，正式四指标汇总只收四项均完整有效的 Ragas 样本，真实全零保留，缺项继续补评。无标准答案的正式路径只跑 F/AR，备用三项不能冒充正式四项。

### 问题 20：评测页面修了什么，验证到什么程度？

旧页面读错字段，用默认 0 掩盖缺失。我改为读取实际 metrics（指标集合）、有效数和完整数，缺项显示“未评出”。已有 Streamlit AppTest（应用交互测试）操作评测流程，核对 `0.75` 显示为 `0.750`、null 显示为“未评出”。这验证界面逻辑；历史记录没有完成真实浏览器截图和控制台验收。

### 问题 21：依赖能 import 就算安装正确吗？

能 import（导入）只说明当前路径暂时能跑，还要检查声明、版本约束、锁文件和安装包。历史环境发现 Streamlit 与 PyArrow 范围冲突，已补 demo（演示）可选依赖和约束。我同步直接依赖、修正 CLI（命令行界面）入口为 `main:main`，收窄打包范围；`uv.lock` 锁定依赖解析结果，`requirements.txt` 包含固定版本和范围约束，未完整锁定 transitive dependencies（传递依赖），pip 安装结果不保证与锁文件一致。

### 问题 22：前端构建为什么也是项目完整性问题？

构建输出若与文档混放，清理命令可能误删其他交付物。当前网页输出到 `frontend/dist`，幻灯片 HTML 输出到 `dist-slides`，移除了失效 PPTX 导出入口和 Windows 不兼容命令。本地 PPT 由参数指定，不随仓库分发；演示内容还应核对当前口径。构建通过只证明打包流程，视觉布局和内容事实要分别验收。

### 问题 23：如何用分层证据验收工程行为？

我按数据流组织验收：源码与依赖检查、回归、SDK边界故障注入、HTTP接口、界面交互、本地数据一致性及原始评分复算。本轮对发现的问题补充复现场景，修复后重新验证，并保留日志与备份。真实服务、并发和模型质量使用各自的联调与评测记录。

### 问题 24：如何向面试官讲述这次工程改进？

我会用缓存案例说明：旧归一化删除小数点，导致不同剂量共用答案；定位后保留语义字符，把来源、策略和历史加入缓存键，并升级命名空间；再用数值和上下文差异回归验证。最后说明知识库版本失效仍需补齐。故障案例同样可以讲错误传播和 L2 不缓存，但不把离线验证扩写成生产事故或未经测量的收益。

### 问题 25：为什么测试套件通过，单独启动仍然可能崩溃？

测试的导入顺序可能提前初始化原生库，掩盖真实入口问题。历史独立进程曾出现 Windows `0xC0000005`（访问冲突），实验发现先导入 PyArrow 再导入相关模块可避开，所以在 Windows 的 `src` 初始化阶段预加载它。证据支持导入顺序与故障有关，尚未用原生调试器确认具体 DLL（动态链接库）根因。

启动包装脚本也修正了外部程序参数中的逗号，并透传退出码。验收要分别跑独立入口和回归；`--help` 通过只证明入口解析成功，模型和数据库是否联通还要实测。

### 问题 26：没有训练好的意图分类器，能否用基础 BERT 顶上？

基础 BERT（双向编码预训练模型）的随机分类头能输出分数，但不具备医疗/通用分类意义，可能让医疗问题绕过检索。当前推理先找正式权重，再找备份，缺权重明确报错；训练脚本才从基础模型开始微调。已有缺权重回归，真实分类质量仍要看独立题集的混淆矩阵和医疗漏分率。

### 问题 27：合并多份评测报告时，哪些细节会悄悄改变结论？

旧逻辑丢弃真实全零样本，又把缺失补零，造成统计不一致。我统一只收正式 Ragas 四项完整、有限、在 `[0,1]` 内的评分，保留全零，排除布尔值、缺项和异常值；去重后用同一批样本计算总均值和裁判分块均值，同时报告 `n_invalid_dropped`（剔除无效样本数）。缺文件报错，无有效评分显示 null（缺失值）。

困难题可能更容易评测失败，剔除它们会高估质量，因此还要保存原始报告并补评。不同裁判若负责不同题块，均值差同时受题目难度影响，不能当成纯裁判差异，也不是逐题 ensemble（集成评判）。
