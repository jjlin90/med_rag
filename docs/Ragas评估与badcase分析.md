# Ragas评估方法与业务案例分析

> 2026-10-10更新：公开说明采用评估参考目标、诊断方法和已实现机制。原始报告、逐题分数及裁判来源在本地留档，参考目标配置见[评估目标与对照方法](quality_pilot_20261010.md)。

## 1. 评估参考目标

| 指标 | 参考范围 | 参考目标值 |
|---|---:|---:|
| 上下文相关性 | 0.65～0.80 | 0.79 |
| 上下文召回率（CR） | 0.75～0.85 | 0.84 |
| 忠实度（F） | 0.85～0.90 | 0.89 |
| 答案相关性（AR） | 0.80～0.90 | 0.89 |

以上数值用于优化规划。项目正式Ragas指标为F、AR、CP和CR，其中Context Precision（CP）描述相关上下文排序精度，按自身定义计算；上下文相关性目标与CP分别维护。

## 2. 题集、模型与记录

历史题集包含210组`question / contexts / answer / ground_truth`，固定20题开发对照采用预先确定的索引、种子、模型和参数。生成端使用问题及实际检索内容，参考答案只用于裁判评分。双方保持同一评分协议，全部问题按索引配对，生成失败、评分失败和已有有效评分分别保存。

原始固定答案与上下文、JSON评分及逐题CSV保留在本地`data/test_query/`；本轮开发记录另存于`artifacts/quality_20261010/`。记录包含题集哈希、生成模型、裁判、提示词、检索参数、指标有效数、完整样本数及补评来源。全量复评使用新输出文件，保留历史记录。

裁判补评仅填原先的缺失单元，保留已有有效评分，并记录每一项来源。不同裁判参与补缺与同题多裁判集成有不同含义，分析时按实际调用方式解释；版本比较同时核对有效样本集合、参考答案和评测协议。

## 3. 四项指标怎样定位问题

F将回答拆成陈述，检查陈述是否受到上下文支持。上下文介绍药物的一般用途，回答却添加具体起效小时数时，应检查这条时间陈述的证据，而不是仅判断整段文字是否看起来合理。

AR通过回答反推问题，再计算与原问的语义相关程度，并使用noncommittal惩罚。回答可能完整复述疾病介绍，却遗漏用户询问的遗传关系；这种情况需要围绕原问题核查回答重点，同时用F约束新增内容的依据。

CP关注相关上下文在返回列表中的排序。若有效资料被相近疾病或泛化段落挤到后面，先检查融合排名、代表子块和重排输入；当前Small-to-Big使用父块下融合分最高的命中子块作为`rerank_content`，精排后把父正文交给生成。

CR检查参考答案关键事实是否得到上下文覆盖。排查顺序是知识库是否包含事实、粗召回是否找到目标子块、父块回溯是否正确，以及最终上下文是否保留所需证据；分别记录各阶段结果，定位资料、召回或选择步骤。

## 4. 实际业务场景

### 4.1 相近疾病导致回答串用

先明确问题中的完整病名和症状对象，检查候选来源、代表子块及最终父正文。若知识库中存在目标疾病资料，但普通检索偏向近邻名称，可开启标题补召回：从实际分块目录匹配完整字面标题，最长优先、最多两个，每个标题补一个限定来源的子块，并在既有预算内回溯去重。显式来源过滤仍限定原资料范围。

生成与评分共用来源标题及正文格式，保留识别疾病对象的实际依据。逐题核查病名、描述对象和结论支持；对照中保存所有题目，使检索改善与新增回答错误能够一起分析。

### 4.2 数值、单位与条件遗漏

体重变化、剂量与周期需要同时读取数值、单位和成立条件。例如“按初始体重计算的变化”需要保留基准，不能只转述一个百分数。缓存规范化保留小数点与单位，问题、来源、策略和历史分别进入键，避免不同条件复用同一回答。

核查时将回答中的关键陈述对应到原文段落，检查是否新增时间、换算或适用条件。结构化复核提供段落编号和支持判断，代码验证结构及编号；证据含义通过逐题阅读和独立评分进一步检查。

### 4.3 起效时间与长期疗程混淆

药物用途、开始起效的时间及持续治疗周期分别回答。资料只介绍用途时，可以先给出有证据的作用说明，并具体指出资料中的时间信息范围。逐题检查是否把长期治疗安排解释成短期起效时间，或把一般规律写成个体结果。

### 4.4 回答相关但没有回应用户重点

固定问题与上下文，检查原问要求的是原因、关系、步骤还是时间，再阅读输出是否回应这一点。有部分有效证据时先回答有依据的部分，再解释具体缺口。压缩套话与无关背景时保留必要条件，配对评测同时看F、AR及关键业务错误。

## 5. 评分与汇总可靠性

- NaN、越界值、布尔值及非有限值记null；真实零分保留。
- 请求过的指标即使整列缺失也保留，报告包含`metrics`、`valid_counts`和`complete_count`。
- 均值按有效值统计，空结果及整列缺失支持保存和展示；完整样本综合先统一样本集合，再用原始精度计算，最终展示时舍入。
- 补评只填缺失单元，保留原裁判与评分来源；备用引擎独立标识。
- 中文AR适配保留公式、严格度和惩罚，双方使用同一语言；评分协议改变时独立留档。
- 模型超时、JSON解析或截断独立记录，已有有效输出按冻结输入保留。

## 6. 如何复现

静态入口使用已有答案与上下文检查评分；实时入口重新检索和生成，检查当前链路。运行需要CUDA、本地BGE-M3及有效裁判接口，接口和密钥配置在私有`.env`中。

```powershell
.venv/Scripts/python.exe scripts/evaluate_rag.py `
  --static data/test_query/eval_answers_210_grounded_v3_ar.json `
  --out-json artifacts/eval_review/report.json `
  --out-csv artifacts/eval_review/results.csv
```

固定20题对照、阶段恢复和参考目标发布方法见[开发对照文档](quality_pilot_20261010.md)。评测时记录模型、裁判、语言、题集和实际调用条件，逐项修改并完整配对；开发集用于方案选择，独立留出题集用于验收。
