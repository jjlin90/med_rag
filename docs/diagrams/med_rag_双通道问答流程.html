与改造前的行为差异

  • FAQ 位置：改造前是「意图分类后的一个分支」，医疗类问题永远不进 FAQ；改造后提升为第一通道，所有 query 先过 FAQ，未达阈值才降级。
  • 意图分类次数：改造前 main_api.py 预判一次 + rag_system.py 再算一次；改造后只在深通道内部执行一次。
  • 检索粒度：改造前父块与子块混在一起返回 Top-8；改造后走 Small-to-Big：子块定位 → parent_id 回溯父块 → 去重 → 精排 Top-2。
  • 阈值语义：改造前靠 _question_relevant() 关键词守卫 hack 兜底误匹配；归一化后该 hack 已删除。

深通道内的分层降级（L0 / L1 / L2）

原则是「降级路径必须比主路径更安全，而不是更粗糙」。

层级触发与行为输出粒度 / 风险
L0正常路径：过滤下推只召回子块，orphan 父块记 ERROR 剔除400 字子块 → 2000 字父块 · 基线
L1子块召回为空 → 放开过滤重查，命中父块后现场切成 400 字子块（共享 SEPARATORS，线上线下同构）仍是 400 字子块 · 风险不上升
L2L1 仍为空 / 基础设施故障 → 安全拒答，不调用 LLM；故障降级结果不写缓存无上下文 · 风险最低

「检索不到就返回 2000 字父块」属于用质量下降伪装成降级，已永久禁止、不提供开关。 回归测试：python scripts/test_degrade_policy.py（9 项 mock 场景）。
