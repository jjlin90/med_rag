# 数据来源与处理边界（代码核验版）

> 以下原说明保留其 2026-09-15 历史口径；2026-09-27 修复后的当前流程见 [架构说明](architecture.md)。缓存键已包含来源、策略与历史；general 提示词已独立；DOCX/清洗/降级传播已修复。历史数据量和评测分数没有因代码修复自动更新。

## 可由仓库证明的事实

- `data/clean_md/` 当前包含 2570 个 Markdown 文件。
- 原始目录 `data/raw/MSDZHConsumerMedicalTopics/` 与抽取脚本提供《默沙东诊疗手册（大众版）》的来源线索；多数清洗文件未保留该名称，不能声称逐篇正文均已标注或独立核验来源。
- `data/raw/` 在 2026-09-15 的统计为 6311 个文件，其中主要是 HTML 与图片等抓取产物；目录中额外的 `.gitkeep` 占位文件不计入语料统计。
- `data/split_docs/docs.json` 当前有 20,816 条记录；按 `parent_id` 统计为 16,880 个逻辑子块、3,936 个逻辑父块。
- 全部记录平均 522.90 字符，子块平均 334.49，父块平均 1330.92，最小 3、最大 2000。

存量分块 JSON 的顶层 `chunk_type` 全部为 `child`，与逻辑父子身份不一致。当前加载旧分块和入库时均按 `parent_id` 纠正类型；查询联合检查 `chunk_type` 与非空 `parent_id`。这些代码不会自动改写磁盘 JSON 或迁移已有 Milvus 集合，存量数据仍需单独验证、迁移。

## 代码实际执行的数据处理

`DocumentLoader` 提供 PDF、DOCX、PPTX、TXT、MD 五种扩展名路由，OCR 是占位实现，旧式 DOC/PPT 不受支持，需先转换。`DataCleaner` 处理字符、页码样式、重复短行、纯符号行、连续重复行和空白；它没有“导航/广告/版权/作者/修订记录”专用语义清理规则。

分块参数为父块 2000、子块 400、重叠 60。分块文件实际位置是 `data/split_docs/docs.json`。

## 不能从代码推出的结论

仓库本身不能证明网页内容的版权授权、公益属性、是否允许再分发、是否完全无个人信息，也不能替代隐私与医疗合规审查。因此本文不再写“无侵权”“无隐私风险”“符合开源合规”等绝对结论。

项目定位和 Prompt 表明其用于医疗科普问答，不应把生成结果当作诊断或处方；但强制免责声明、诊疗风险分级和完整内容安全策略并未在所有回答路径中实现。

## 使用前应补的外部证据

1. 数据授权或许可条款及抓取日期。
2. 原始页面到本地文件的来源清单与哈希。
3. 个人信息扫描报告。
4. 医疗免责声明和高风险问题的产品验收记录。
5. 数据更新、删除与版权投诉处理流程。
