## 2. 可以直接讲的项目介绍

### 30秒版本

> 这是一个医疗科普RAG项目，让回答基于可核对的本地资料。以MinerU解析并清洗2572篇文档，用子块检索、父正文补充上下文。在线先查缓存与条件FAQ，再按意图进入医学检索或通用生成，医学链路用BGE-M3双表示、Milvus加权融合与BGE重排。我重点关注缓存隔离、故障透明化和评测证据，当前110项工程回归通过，模型质量另外通过固定题集与逐题分析评价。

### 两分钟版本

> 项目包括离线建库、在线问答和评测。离线先以MinerU抽取本地手册HTML正文，清理链接目标与HTML标记并保留标题、列表、表格和数值，再按2000/400字符父子切分，本地新方案形成4064父块与17629子块。子块保存父ID和父正文，通过BGE-M3生成dense和sparse。正式流程可以写入Milvus；本轮新语料完成本地重建与内存检索实验，尚未切换线上集合。
>
> 在线API先查包含来源、策略和实际历史的缓存；没有额外约束才尝试FAQ。FAQ除BM25相对门槛，还检查标准问题一致，避免人群或方向只差几个字就误直答。未命中后BERT分类：通用问题直接生成，医学问题选择四种策略。正常每次融合最多16个子块，取前5个按父ID聚合，以代表子块精排，最多2条上下文供生成。
>
> 工程上，我把正常空召回与依赖故障分开。L1放宽过滤，命中父块后切为子片段；检索和重排故障进入L2，阻止最终生成。生成失败但有证据时返回原文摘录，L2不缓存，响应公开降级原因。

> 评测同时看Ragas四指标与逐题证据。历史210题是混合裁判补缺后的固定答案评分，不是临床准确率；本次复算数据与评分、完成110项通过的回归并加入索引清洗，并修了通用提示冲突、跨子查询证据丢失、训练去重和评分来源声明。真实全链路与生产吞吐仍需独立验收。

## 3. 流程和技术原理

### 3.1 离线与在线入口

```text
HTML → extract_msd.py → clean_md
入库：加载→清洗→父子分块→保存JSON→双表示向量化→Milvus insert

API：请求校验→query缓存→条件FAQ（faq缓存/BM25/MySQL）
    →核心分类：general→独立通用提示→生成
               medical→策略→检索→聚合→重排→证据生成
    →会话保存→合格结果缓存→响应
```

抽取是单独入口，正式入库不会先自动抽取HTML。加载支持PDF可提取文本、DOCX段落、PPTX文本、TXT、MD；OCR是占位，复杂表格、图片和跨页结构未闭环。分块/向量化失败或数量不符会停止，但多批insert不是全库事务，后批失败可能留下前批数据。

FAQ/general的sources通常为空；医学分支返回实际候选，但没有逐句证据认证。`used_cache`只标记外层缓存，FAQ内部缓存命中也可能返回false。降级字段准确名称是`degraded`、`degrade_level`、`degrade_reason`。

默认无医学证据不调用最终答案生成器；此前选策略/增强仍可能调用LLM。主路径重排失败返回L2，不静默沿用原排名。生成失败且有证据时最多给2段原文、每段500字符。

### 3.2 BGE、索引、融合与精排

BGE-M3提供dense、学习式sparse及多向量，本项目用前两种；sparse词项来自模型tokenizer，不是jieba统计BM25。选择依据是双表示和中文/多语言、本地集成，未证明医疗任务最优。[BGE-M3官方说明](https://huggingface.co/BAAI/bge-m3)

不能说标准BGE-M3在本项目支持任意套娃截断；未启用Matryoshka训练/降维验证。Late Chunking与ColBERT属于扩展方向，不是当前成果。2048是编码截断上限，不能用2000字符证明绝不截断。

单位向量满足`cos(x,y)=x·y`、`||x-y||²=2-2x·y`；应核对实际归一化配置和向量范数。排序关系不能证明某度量一定更快。IVF_FLAT搜索部分簇，是近似检索；FLAT全扫描，HNSW图搜索。当前参数需要召回/耗时对照。

WeightedRanker转换各路分数后加权，RRF用`Σ1/(k+rank)`融合名次。当前用前者，没有RRF实验；权重不是候选比例或正确概率。[Milvus 2.5融合说明](https://milvus.io/docs/v2.5.x/reranking.md)

父子方案以存储冗余换少一次回查；400字符子块也可能不完整。主路径CrossEncoder用代表子块，生成看父正文，减少长父文的截断和稀释，但代表子块可能遗漏父块其他相关部分。标题补召回默认关闭，开启时标题组优先、组内按精排分；不能承诺多个主题最终均覆盖。

### 3.3 Ragas四项怎么计算

| 指标 | 计算思路 | 局限 |
|---|---|---|
| F | 回答陈述中受上下文支持的比例 | 忠实于错误资料也可能高分 |
| AR | 答案反推问题，与原问求平均嵌入余弦，默认3个；有noncommittal惩罚 | 不检查事实正确性，合理拒答也可能低分 |
| CP | 判相关上下文，按相关位置累积precision@k再归一化，关注排序 | 不是简单相关块数/总块数，也不是上下文相关性 |
| CR | 参考答案陈述被上下文支持的比例 | 不是document Recall@K，依赖参考答案 |

整批都有非空参考答案才算四项，否则只F/AR。AR余弦理论可为负，本地契约将[0,1]外值记缺失。布尔值、非有限值、缺失不当0；真实0保留，报告各指标有效数与完整数。备用自定义裁判引擎独立标记，不能混作正式Ragas。[Ragas AR](https://docs.ragas.io/en/v0.2.6/concepts/metrics/available_metrics/answer_relevance/)、[CP](https://docs.ragas.io/en/v0.2.6/concepts/metrics/available_metrics/context_precision/)、[CR](https://docs.ragas.io/en/v0.2.6/concepts/metrics/available_metrics/context_recall/)

**追问：RAG一定更好？** 不一定，要看更新、证据、成本、延迟和可用数据；检索错了也会答错。

### Q06 你具体负责什么

按真实贡献说“哪些函数改了，什么输入会错，怎样复现验证”。可讲缓存保留符号、FAQ一致性、评测缺失；本次新增通用提示隔离、跨子查询证据保留。仓库有某模块不等于本人从零研发。

**追问：现场证明？** 展示函数、失败样例和对应回归，解释改前改后。

### Q07 最难的问题

FAQ高softmax却错人群很适合讲：相对排序不能证明医学等价，单候选更是固定1。我增加标准问题一致性，用条件替换探针核对路由行为。

**追问：牺牲什么？** 同义改写进深通道，成本和延迟增加；没有标注支撑时先减少误接受。

旧缓存规范化曾让1.5mg与15mg相同；现仅去首尾空白，来源/策略/历史进键。FAQ相反类别误接受82→0只代表特定探针，不代表医学正确率100%。

**追问：防复发？** 回归涵盖小数、比值、人群、反义及旧键隔离；版本缓存仍需补。

### Q09 给Markdown，从零设计RAG

先定任务、来源与拒答边界，抽样检查重复、数字、表格、授权，保存来源位置。建立简单检索和标注基线，再对照加入父子、融合与精排，不能先堆复杂策略。

**追问：一开始用父子吗？** 与固定切分比较证据覆盖、回答错误、token和延迟再决定。

### Q10 来源、规模和格式

本地按默沙东大众版组织；MinerU清洗方案2572篇、21693块，旧语料2570篇、20816块分别留档；新旧父子引用均已核对。格式支持见第3节，授权、采集时间、逐篇URL需来源材料确认。公开可访问不等于可任意商业分发。

**追问：线上也是21693？** 必须连目标部署核对计数和字段，本地文件不能代替。

### Q11 如何切块，为什么400/2000

递归字符切分，子400定位、父2000补前后文、重叠60缓解边界丢失。参数是初值，需消融；不是“400字总能完整表达医学事实”。

**追问：与token关系？** 用真实tokenizer统计长度与截断率，不按字符数猜。

### Q12 为什么Parent-Child

分开检索粒度与生成窗口，以冗余正文换回查。代价是存储、更新一致性、噪声及去重后的多样性减少；缺父正文回退子正文。

**追问：所有文档适合？** 短FAQ、表格或条款可能更适合结构化/语义单元，需对照。

### Q13 为什么BGE-M3

双表示、中文/多语言与现有本地部署兼容。关闭ColBERT控制复杂度；没有全模型消融，不能说医疗任务最优。

**追问：sparse能保证数字不串？** 不能，亚型/人群/数值需真实badcase和标注集验证。

### Q14 为什么Milvus而非FAISS/ES/pgvector

当前需要双向量字段、过滤、持久化和服务接口，Milvus适配。FAISS偏检索库，ES适合全文体系，pgvector适合关系数据集成；2万块不意味着必须分布式数据库。

**追问：换库代价？** 重建索引，核对分数、过滤和错误语义，以同题集验召回与延迟。

### Q15 dense与sparse

Dense匹配语义改写，sparse补共同词项；两者可能互补，也可能一起混淆近邻疾病。后续精排与事实核查仍必要。

**追问：如何证明互补？** 对照dense-only、sparse-only、融合的覆盖和错误，别只举机制例子。

### Q16 混合权重如何确定

当前1.0/0.7是配置初值，没有网格搜索证明。转换分数后融合，不等于原始分直接加，也不是59%候选来自dense。

**追问：怎么调？** 固定标注集测Recall@K、NDCG/MRR和延迟，与RRF及单路比较。

### Q17 为什么rerank

双塔预计算文档、适合大范围召回；CrossEncoder交互编码、适合小候选集。主路径用原问题+代表子块评分，再给父正文生成。重排找不回未召回的资料。

**追问：失败怎么办？** 主路径L2/reranker_unavailable，阻止最终生成，不缓存。

### Q18 TopK/TopN怎么定

目前每次16→前5聚合→最多2上下文，只是预算配置。分别改变粗召回、聚合、上下文数，测证据和主题覆盖、精排耗时、token与回答错误。

**追问：越多越好？** 计算、噪声和输入限制会增加，需联合取舍。

### Q19 FAQ与RAG怎么路由

外层缓存优先，无历史/source/显式strategy才试FAQ，原始分、相对阈值和标准问题一致共同控制。未命中进入核心，分类仅在这里执行一次。

**追问：精确匹配为何还BM25？** 当前保留候选门槛，也会漏精确问题；可比较精确查询基线，并处理同题多答案冲突。

### Q20 分类错了怎么办

故障和非法标签会L2；有输出但错分类目前不会纠正。medical被判general会跳过检索，通用提示的诊疗限制不是安全保证。需真实困难集和医疗召回优先路由。

**追问：历史1.0可信吗？** 旧模板同源且本次发现10条原样跨集，不能当真实线上准确率。

### Q21 检索不到怎么办

正常空召回先L1放宽过滤，父块现场切子片段；仍空固定资料不足回复。服务错误直接L2不试L1。默认阻止最终无证据医学生成。

**追问：全库没有吗？** 只能说当前未取得证据；可能是语料、过滤、索引或问句问题。

### Q22 如何减少幻觉

保留条件、减少错召回、精排、来源标题、strict grounding和无证据拒答协同。可选复核检查结构与证据编号，失败不发初稿；语义支持仍需评测。

**追问：有来源就是正确？** 不是，资料可能无关、过时或缺条件，当前也没有逐句强制对应。

### Q23 定位召回还是生成问题

逐层看原文、清洗块、粗候选、精排上下文和答案。库里没事实是覆盖，没召回是检索，有候选却丢掉是选择，提示里有却增补/串用是生成；多层可同时出错。

**追问：先调Prompt？** 先确认证据进了实际提示，Prompt补不回漏掉的资料。

### Q24 Ragas结果是多少

历史210题F/AR/CP/CR=0.8163/0.5007/0.8405/0.7619，均值0.7298，正确文件见第1节。混合裁判固定答案评分，本次仅复算；20题开发对照另报未提升结论。

**追问：准确率提升20%？** 不能这样说，样本/答案/协议不同且不是临床准确率。

### Q25 为什么不能只用Ragas

裁判有随机性、语言偏好，参考答案也会错；忠实于错误原文可高F，合理拒答可低AR。补人工条件/单位/危险建议核查、拒答、失败率、延迟与成本。

**追问：人工怎么评？** 预定量表、盲评双方、记录分歧；医学质量需要合适的专业审阅。

### Q26 重做优先改什么

先保证数据与评测可信，再建立召回标注与可解释基线，固定对照逐项调检索和生成；补指代、版本缓存、监控。部署治理按实际需求推进。

**追问：直接换大模型？** 不能修泄漏、错缓存、丢证据和分母错误，还改变实验条件与成本。

### Q27 Transformer/自注意力/BERT/BGE

注意力典型形式softmax(QKᵀ/√d)V；BERT双向编码，本项目分类头学路由；BGE为检索表示训练，reranker共同编码问题和候选。架构相近不代表目标与输出相同。

**追问：基础BERT做向量行吗？** 可构造，但未经检索训练和pooling验证，不能期待同等效果。

### Q28 temperature/top_p/top_k

温度调整分布，top_p取累计概率集合，采样top_k取最高概率K个token。项目显式温度0.2，未显式设另两项；检索TopK是候选数，含义不同。

**追问：温度0正确且稳定？** 不保证，确定采样也会错，供应商执行与模型版本可能变化。

### Q29 高并发

当前async路由内有同步模型/IO，会阻塞事件循环，未做生产压测。测各阶段后设置准入、deadline、资源隔离；线程池也需处理共享SQL游标和GPU并发，多个worker会重复加载模型。

**追问：async足够吗？** 不够，它不会自动把阻塞调用异步化。

### Q30 一句话讲亮点

“子块定位、父正文生成，约束输入隔离缓存，失败显式降级，用逐题证据检查效果。”落在可验证机制，避免说彻底消除幻觉。

**追问：最扎实成果？** 选可复现输入和日志的修复，讲测试范围与剩余限制。

### Q31 失败、超时与重试

当前有异常捕获和分层降级，没有统一deadline/熔断。裁判有单独超时与重试设置，生成端SDK也可能自动重试，不能说所有接口都不重试。重试只针对可恢复错误，有限次数并计入总预算。

**追问：超时就是取消吗？** 不是；请求返回后后台线程或供应商仍可能执行，要跟踪和限制残留工作。

### Q32 前公司信息

公司、岗位、任职时间、团队和职责据实回答。涉保密内容说明可讨论范围，讲个人承担的模块与协作方式。本项目定位不能自动改写为某公司生产系统。

**追问：你是负责人？** 区分独立实现、协作、复现和代码修订，用实际提交或成果支持。

### Q33 上份与期望薪资

按真实薪酬结构说明固定、奖金和其他部分；期望给本人可接受范围，关联岗位职责与总包。稿件没有这些信息，应自行填写，不编收入。

**追问：为什么这个范围？** 结合个人能力、岗位要求和本人真实选择，不用项目分数换算薪资。

### Q34 客户认为效果差，但工期到了

先具体化为遗漏、错病种、数值、证据或延迟，固定失败样例和可交付范围。优先修高风险问题；暂时缩小范围或明确降级，通过双方认可的验收题沟通质量，不用均值掩盖危险错误。

**追问：来不及全部修？** 交付可验收的范围和剩余风险，保留回滚；没有真实客户经历就按设计题回答。

### Q35 表格、图片、跨页表

当前OCR和表格结构未完整落地。设计上提取标题、表头、单位和脚注，跨页匹配同表，保留原页位置；检索块应携带行列语义。扫描图先OCR并验数字，不能说当前已支持全部多模态。

**追问：只把表格转文本？** 必须保留字段归属与单位，否则数值对应关系丢失。

### Q36 更新、重复与脏数据

当前有清洗和全量入库，完整增量、幂等、删除传播还未闭环。以来源/版本/位置定义稳定ID，校验内容和父子关系，在影子集合构建后验收切换。

**追问：重复insert会怎样？** 不能把insert说成业务幂等upsert；部分写入和更新语义需结合实际数据库验收。

### Q37 FLAT/IVF/HNSW如何选

FLAT可做精确基线；IVF通过簇数和探测数折中；HNSW通过图参数折中，内存和构建成本不同。当前IVF_FLAT，没有HNSW实际测试。

**追问：为什么256/16？** 是现有配置，需按过滤后的分布、规模、召回和延迟验证，不宣称理论最优。

### Q38 MySQL/Redis/Milvus分工

MySQL保存FAQ标准答案和会话；Redis缓存问答与FAQ；Milvus保存向量及正文/关联字段并检索。三者不是互相替代的数据库，Redis故障会增加后端负载。

**追问：缓存挂了？** 当前绕过，生产需回源限流与熔断，不能让全部请求无限制压到LLM。

### Q39 Milvus只存向量吗

不只。当前有text、parent_id、parent_content、source、metadata和新schema的chunk_type。检索返回正文/来源，父正文可直接恢复；本地JSON是构建产物。

**追问：为什么冗余父正文？** 少一次回查，代价是空间、写放大和更新一致性。

### Q40 BM25、混合检索与RRF关系

FAQ是jieba+自写BM25；知识库是BGE dense/sparse+WeightedRanker；RRF是名次融合替代方案，当前没有使用。融合不能与CrossEncoder精排混为一层。

**追问：softmax与RRF？** softmax把本组候选分数变相对分布；RRF合并多路名次，目的不同。

### Q41 检索不准怎么定位

固定问题，检查原文有无事实、数字是否清洗丢失、问句增强、过滤、编码、单路候选、融合、父子恢复和精排。分别测召回与排序，不只看最终回答。

**追问：nprobe加大一定修复？** 只扩大近似搜索范围，不能修原文缺失、错过滤或模型语义问题。

### Q42 rerank分数是概率吗

当前compute_score输出排序分，未做正确率标定；融合分、精排分、BERT分和FAQ固定0.95含义不同。UI不能将它们都展示为答案正确百分比。

**追问：sigmoid后？** 映射到0～1仍不等于校准，需独立标注和校准评测。

### Q43 为什么多种改写策略

direct保持原问；HyDE生成假设文本；subquery拆任务；backtracking抽象背景。各有漂移/成本风险，当前LLM四选一，失败回退direct，未证明每类自动选择最优。

**追问：原问保留吗？** 原问用于最终重排/生成；HyDE和回溯当前只用增强文本检索，没有自动再融合原问分支。

### Q44 快速/复杂问题怎么路由

当前快路径来自外层缓存和严格FAQ，没有单独训练fast/complex分类器，也没有Chunkless路径。医学核心再选四种策略，所有策略走父子检索。

**追问：复杂度能决定安全？** 不能，短问题也可能有关键条件或高风险，路由需保留这些条件。

### Q45 短问题、多轮指代

history进生成不等于进分类和检索。当前“那这个呢”可能错路由/错召回。设计上用历史解析成独立检索问句，保留原问与条件；指代仍不清就澄清。

**追问：只传session_id行吗？** 不行，服务端不自动取历史，客户端需要提交messages。

### Q46 历史过长或换话题

当前提示只取3条消息，可能从助手消息开始，并不保证完整3轮。未来按token预算保留完整轮次、主题状态和可核对摘要；话题变化时避免旧实体影响检索。

**追问：缓存怎么跟进？** 当前键包含完整实际历史，版本与摘要改造后也要进入键或主动失效。

### Q47 MCP与Function Calling

Function Calling通常由模型输出结构化调用意图，应用校验并执行；MCP是客户端与工具/资源服务交互的协议，强调发现和接入。可以共同使用；本med_rag主链没有MCP工具服务或自主Agent循环。

协议定位可核对[MCP官方概述](https://modelcontextprotocol.io/docs/getting-started/intro)。

**追问：工具自己执行吗？** 仍需宿主权限、参数校验、结果处理；结构化调用不等于授权。

### Q48 防提示词注入

来源过滤已用JSON字符串转义，不能再说原样拼接漏洞未修。检索正文和历史仍是不可信输入，要与系统指令区分、限制可执行能力，并做注入样例回归；当前没有完整注入防护或逐句输出验证。

**追问：转义就安全了吗？** 只保护过滤表达式结构，不等于文档ACL或模型指令隔离。

### Q49 多租户和文档权限

当前无认证、会话所有权或文档ACL。部署时将用户身份、租户与资料权限在检索前强制校验，缓存包含权限范围；会话查询/删除也校验所有权。

**追问：UUID够安全吗？** 难猜标识不是授权，不能凭session_id允许任意访问。

### Q50 回答慢怎么优化

先量各阶段，包括首次加载、编码、Milvus、改写、重排、生成和存储。缓存、减少不必要改写、控制上下文、批处理和资源隔离都可对照；当前本地模型是GPU，不再说主要是CPU精排。

**追问：流式能提升吞吐吗？** 它主要改变首字体验，不自动减少总算力；当前HTTP未接流式。

### Q51 为什么FastAPI/Docker Compose

FastAPI提供请求类型、校验和接口文档。Docker/Compose可组织依赖、健康与卷；但当前仓库未提供完整应用Compose部署闭环，不能把本地依赖容器说成已交付生产部署。

**追问：async优势实现了吗？** 当前同步调用仍会阻塞，要先拆执行和连接生命周期。

### Q52 线上故障怎么排查

设计上从影响范围、变更版本和依赖状态切入，沿缓存、FAQ、路由、检索、重排、上下文与生成定位。当前有日志、health和检索计数，无统一request_id、分布式追踪与自动熔断。

**追问：health绿色可靠？** 部分只检查初始化对象/集合存在，不证明实时推理、索引完整或质量正常。

### Q53 知识库更新如何发布

当前未闭环影子/灰度发布。方案是冻结语料与模型版本、构建新集合、验计数及父子关系、固定题集与探针，通过别名或路由切换，保留旧版本和回滚。

**追问：回滚只切向量库？** 还需让模型、提示、知识与缓存版本一致，避免新旧答案混用。

### Q54 分层评估RAG

数据层验完整与数字；检索层测标注Recall@K/NDCG；回答层测四指标和人工错误；系统层测错误率、拒答、延迟与成本。110项通过的回归主要是工程行为，不替代其余层。

**追问：CP等于检索Precision@K？** 不直接等同，它采用裁判相关性与排序公式，标注与分母不同。

### Q55 为什么30/210题不够

样本量只是一个因素，更要看疾病、人群、问句、难度和拒答覆盖。固定20题反复调参会过拟合，应另留不参与选择的测试集，并按来源/实体/模板隔离近重复。

**追问：需要多少题？** 结合目标指标、效应大小和置信区间估计，不机械给一个通用数量。

### Q56 怎么评业务价值

当前没有真实用户收益证据。未来测找到可用资料的成功率、人工检索耗时、来源核验、恰当拒答、投诉和成本，结合有对照的用户任务，不能用Ragas均值代替满意度。

**追问：有访问量就有效吗？** 使用量、任务成功和安全质量是不同维度。

### Q57 最容易被追问的风险点

准备回答：来源授权；本地计数与线上区别；权重/TopK初值；代表子块局限；分类泄漏；混合裁判与未覆盖的全链路；版本缓存；多轮检索与并发治理。

**追问：为什么保留不足？** 解释真实取舍与下一步如何验，不回避，也不把规划说成成果。

## 5. 新补20个深入追问主题

### Q58 confidence究竟表示什么？怎样真正评估答案可信度？

当前FAQ固定0.95，医学RAG通常用意图分类分，L2为0；它没有评估答案陈述正确率。应把路由分、证据覆盖、生成核查与答案质量分开呈现，用独立标注集评价置信区间、校准误差和选择性回答表现。

**连续追问：0.95需要改成0.8吗？** 换常量无意义，先改名称/说明，再设计标注与校准。**阈值以下全拒答？** 要看覆盖与错误代价，不靠未标定分类分决定答案可答性。

### Q59 MD5/SHA-256为什么没有解决旧错缓存？

问题在规范化：1.5和15先变同串，再强的哈希都得到同键。正确顺序是保留语义差异、加入影响输出的维度，再摘要。v3隔离旧结果不需要清共享Redis；医学剂量不能随意单位换算后合键。

**连续追问：换SHA能消灭碰撞吗？** 降低摘要碰撞概率，不能修输入别名。**session_id是否入键？** 当前历史相同可复用；若答案依赖权限/用户信息，身份权限范围必须纳入或关闭共享。

### Q60 数据泄漏怎么发现、怎么修，为什么还不能报100%？

本次用原样text集合交集发现10条跨集问题；训练4485条只有4447个唯一text。新构建器先裁剪首尾空白、去重、拒绝矛盾标签，再按类别平衡和分层切分，避免原样跨集。旧模型未重新训练，历史成绩不能改写成净化后的成绩。

**连续追问：去重足够吗？** 不足，同病种不同模板仍可跨集；还要按实体/来源/模板分组，独立真实困难集。**加大验证集？** 若同源泄漏未处理，数量再大也可能乐观。

### Q61 总有TopK返回，怎么判断“真正无可用证据”？

非空结果只证明有候选，不证明相关。当前L1主要在空召回触发，没有统一相关性拒答阈值；strict prompt也不是校准器。用无答案/近邻疾病/条件冲突样本，评证据充分性并标定拒答策略。

**连续追问：用最高rerank分即可？** 未标定且分布依赖模型、长度、语料；要用困难负例和覆盖/误接受曲线。**从没查到到全库没有？** 不能直接推出。

### Q62 A、B并行，C依赖两者，B超时怎么办？

先区分B是必须证据还是可选增强。必须分支故障应停止C或明确有限回答；可选分支可跳过，但保留主分支错误。当前subquery串行，任一路error整体L2；可选标题补召回失败跳过，对照这两条语义即可解释取舍。

**连续追问：Future超时后取消了吗？** 通常不能终止已运行同步线程，需下游超时、残留任务计数及资源限制。**最多等多久？** 剩余总deadline而不是每路重复用完整预算。

### Q63 为什么有sources还不能叫“逐句可溯源”？

sources是最终候选资料清单，不证明每句话与资料对应。可选复核校验编号/结构/引用文本，不能自动证明语义蕴含。要把关键陈述链接到原文位置、完整条件和版本，再抽查支持/矛盾/未支持。

**连续追问：引用编号有效就够？** 不够，句子可能只支持一半。**原文摘录兜底必然安全吗？** 也可能不相关或截断条件，因此明确未经解读并核查。

### Q64 HyDE编的答案会污染知识库吗？如何控制漂移？

当前假设文本只用于检索，不入库、不是生成证据；但可能引入错疾病/药名，导致错召回。最终用原问重排与生成不能保证修回。可比较原问与HyDE双路、保留关键条件、限制增强和标注困难题。

**连续追问：增强失败返回什么？** 当前回原问。**策略选择器就是Agent吗？** 当前只是一次受限分类式选择，没有自主规划与工具循环。

### Q65 怎样证明优化有效，而非挑题/评分噪声？

冻结问题、参考答案、模型、协议，先登记比较范围和指标；双方同题配对，用置信区间和badcase检查。一次只改目标因素，开发集选方案，留出集验收。本次20题candidate F/AR略低且区间跨0，只能说未获得改善证据，不能说新方案显著更差。

**连续追问：CP/CR为何相同？** 冻结问题/上下文/参考答案的回答层实验可复用该两项，不能拿它证明检索改进。**混合裁判比较？** 保持双方逐项同协议，记录来源；不同题块均值差不是纯裁判差异。

### Q66 null、0和被剔除样本怎样报告？

0是有效低分，null是未得到有效评分；429、截断与解析失败记原因和尝试，不补0。每项均值用有效分母；综合或配对比较统一完整样本集合，同时报告总数/有效数/失败数和失败题型。

**连续追问：剔除失败会不会高估？** 会，困难题更容易失败，应补评或披露偏差。**只补缺失？** 保留已有评分和来源，不反复重评挑高分。

### Q67 模型名、提示、语料和裁判怎样留证？

记录代码版本、数据/问题/上下文/答案哈希、模型实际标识与供应商、提示全文、参数、时间及逐项裁判来源。生成模型缺标识时只能说独立性未验证；本次静态报告已修这种错误声明。不同名称也可能是同模型别名。

**连续追问：哈希证明什么？** 证明输入字节身份，不证明内容真实/模型执行符合声明。**本地留档别人可复现吗？** 数据和权重被忽略，需相应材料和环境；公开摘要不是独立复现。

### Q68 2万块变200万块，入库和检索先改什么？

先量存储、冗余父正文、向量、索引内存与过滤分布，再设计稳定ID、增量、删除传播、批写与检查点。当前insert多批有部分成功风险，没有全流程事务或成熟增量。候选预算和索引参数随分布重新验，不直接照搬。

**连续追问：失败后从头重跑？** 可能重复/混版本，要幂等和检查点或影子集合。**父正文要一直复制吗？** 可比较外部文档存储回查与内联的总成本及延迟。

### Q69 单次问答成本与P95怎么算？

分路径：缓存/FAQ省该次深调用；医学自动策略增加一次LLM，增强可能再一次，最终生成一次，复核开启再一次；subquery增加多路检索。记录实际token、供应商计费、GPU耗时、存储与错误重试，汇总真实负载分布。

**连续追问：平均很快就够？** 看P95/P99、首字与总时延、冷启动、失败率。**现有response_time可直接当HTTP总时延？** FAQ/RAG在会话缓存写入前计时，需客户端端到端测量。

### Q70 SDK重试与业务deadline如何协调？

客户端构造未显式统一生成超时/重试，安装SDK存在默认行为；裁判单独设超时/重试。先核对实际版本和参数，将连接、读、排队、推理、回退计入同一deadline。重试用退避与抖动，仅对可恢复错误，并控制额度和并发。

**连续追问：取消请求能退费吗？** 不能保证，远端可能已处理。**所有异常重试？** 鉴权、非法参数、稳定格式错误通常需修原因，不能无限重试。

### Q71 history与会话访问的安全边界？

历史既包含用户信息也可能包含旧错误答案，只用于理解对话，不能自动作医学证据。当前无会话所有权检查，日志也会记query，应补认证、最小化留存、访问控制和脱敏；CORS不是认证。

**连续追问：保存5轮就合规？** 数量限制不代替目的、权限、期限和删除机制。**缓存中有历史？** 键是哈希，但缓存答案仍可能含个体内容，应限制跨用户共享。

### Q72 数值、单位与token截断如何验？

原文、清洗、分块、编码与提示分别检查数值和成立条件；统计embedding及query+子块精排的实际token长度。2048上限不等于每块都不截断，max_tokens1024也不是完整输入预算。

**连续追问：40%降重可换算公斤？** 没有基准不能自行换算；问答必须保留原单位/条件。**400子块还会截断？** 可能，query与特殊token也占预算，需真实tokenizer测。

### Q73 标题补召回有什么新风险？

它根据本地真实标题字面匹配，可帮助区分近邻疾病，却会引入目录版本依赖和规则偏置；最多两标题、既有候选预算，优先级会改变纯模型排名。多主题还可能被同一主题多个父块占满最终2条。

**连续追问：目录坏了？** 当前记录告警并保留普通检索。**某标题失败？** 只跳过可选路；主检索失败仍L2。**合并为何要保留标记？** 跨子查询较高分普通命中不能覆盖已确认标题依据，本次已修。

### Q74 最高分代表子块能代表整个父块吗？

它是计算预算下的代理，不是充分证据。父块不同位置可能各支持一个子任务，用一个子块精排会遗漏其余相关信息。可比较子块先精排再回溯、多代表拼接、滑窗取最大/聚合，约束长度和多主题覆盖。

**连续追问：父块整段精排？** 可能截断或被噪声稀释；要测实际token窗口与召回。**多路同父证据？** 保留children_ids并选最高融合分代表，本次合并已补齐。

### Q75 怎样做有意义的工程测试？

测外部可见结果：错缓存不得复用，故障阻止生成，缺评分保留，来源约束不放宽，未完成生成不发布。替身帮助定位编排，但必须另测真实SDK/模型/服务。测试日志中的注入异常不是测试失败，要看断言和退出码。

**连续追问：为什么81项还漏问题？** 原通用测试只看调用次数，没看实际提示；合并缺跨路标题证据场景。新增断言先复现失败，再修代码；测试数量不能保证没有缺陷。

### Q76 医疗拒答策略怎样评价？

分别测可答、部分可答、资料不足、个体诊疗和危险问题，评价正确支持、适当拒答与不必要拒答。严格grounding允许先给已支持部分，具体说明剩余缺口；免责声明不是安全系统。

**连续追问：F高AR低怎么办？** 看遗漏/拒答和问题重点，不能为追高AR添加无证据建议。**临床验收？** 需要专门标准和专业审阅，本项目没有这个结论。

### Q77 面试官要求现场解释一次修复怎么讲？

用“四步”：具体触发→根因→改动→验证。例：general+空context仍生成strict医学用户提示，导致与通用系统提示冲突；修为显式系统提示使用独立用户提示，保留最近3条历史，医学默认路径继续grounding。回归检查实际发送内容与核心路径，而不是假模型输出看似正常。

**连续追问：验证了模型回答质量吗？** 这次验证提示与编排，没有新外部模型对照。**另外两类改动？** 跨查询合并保留标题/子证据，训练先去重及冲突检查；评分来源不全则不声称独立裁判。

## 6. 故障场景：把当前行为与生产设计分开

| 场景 | 当前行为 | 继续追问时解释的边界 |
|---|---|---|
| Redis未初始化/GET或SET报错 | 按无缓存继续 | 目前连接/读超时5秒；没熔断、SingleFlight或回源并发保护 |
| FAQ/MySQL不可用 | FAQ未命中，进入深通道；会话保存可能失败 | FAQ与会话各用长连接/游标，没有成熟连接池与重连；不能保证持久化 |
| BM25高分但不同标准问题 | 拒绝直答，走核心 | 相对分不是等价证明；标准答案本身另审 |
| 存量父标签错/孤儿子块 | 类型按父关系恢复；子块过滤联合父ID；孤儿打点剔除 | 本地修复不等于在线集合迁移，仍需数据验收 |
| 正常子块空召回 | L1放宽过滤，父块现场切子片段，候选限量 | 只放宽子块条件，来源约束仍保留；可能降低覆盖，需独立评估 |
| L1仍空 | L2资料不足，默认跳过最终生成 | 选策略/增强可能已发生，不能说整次零LLM调用 |
| embedding/Milvus异常 | L2/retrieval_error，不试L1 | 启动失败与已启动请求级故障不同 |
| subquery任一路故障 | 整体L2，成功分支也不能掩盖故障 | 部分回答可作为未来策略，但需显式缺口及对照 |
| 可选标题补召回失败 | 告警、跳过失败补路，保留主路与其他成功路 | 主检索故障仍L2，不能吞掉主错误 |
| 意图故障/非法类 | L2/intent_classifier_unavailable | 有输出但错误分类目前无自动补救 |
| reranker缺模型/推理异常/坏分数 | 主路径L2/reranker_unavailable | 不能说自动保留粗排；未接超时熔断 |
| LLM异常/截断/空内容 | 生成器拒绝不可发布正文；医学有资料时原文摘录L2 | 接口错误、复核失败统一llm_unavailable，详细类型靠日志 |
| 必需复核失败 | 不发布初稿，走原文摘录L2 | JSON/编号校验不代替语义审阅 |
| 多轮短追问 | 生成有最近历史，分类/检索主要看当前问 | 需要指代改写；当前不会自动完成 |
| 评分429/超时/无效分 | null、有效数与完整数分开；有限补缺 | 不能补0、删低分、混裁判后声称统一新评测 |

**一分钟口述：** Redis/FAQ是可绕过的加速能力；检索和重排是当前医学生成的必要环节，故障就明确L2。有证据但生成不可用时给原文摘录，L2不缓存，避免故障被TTL放大。请求级降级不能解决无限回源，生产还需deadline、连接池、限流、熔断、模型隔离和监控。当前health计数主要是检索分支，不是全请求故障计数，子查询分别计数、重启清零。

## 7. Redis、熔断和一致性的口述基础

| 问题 | 原因 | 处理与限制 |
|---|---|---|
| 穿透 | 请求不存在的数据，每次miss回源 | 参数校验、短空值缓存、布隆过滤与限流；随机key仍可能回源 |
| 击穿 | 一个热点key失效，大量并发回源 | SingleFlight/锁、提前刷新；旧值只用于允许陈旧的业务 |
| 雪崩 | 多key同时失效或Redis故障 | TTL抖动、高可用、限回源、熔断和降级 |
| 一致性 | 缓存与权威数据源不同步 | Cache Aside通常先写库再删缓存，仍有旧读回填竞态 |

Cache Aside不是强一致。TTL、版本、CDC/失效重试可降低不一致；延迟双删不是完整证明，分布式锁也不能自动保护所有读写路径。医疗知识更新还需让缓存绑定知识版本。当前v3是接受策略命名空间，不代表动态知识版本已实现。

SingleFlight合并同key回源，不是全局限流；锁需限定租约、唯一令牌、校验后释放，并防锁失效后的旧结果覆盖。布隆过滤器存在误报，标准形式不适合直接删除；也不能用它判断任意自然语言问题是否可答。以上属于设计知识，当前项目未落地。

熔断Closed统计正常调用，Open暂停，Half-Open少量探测恢复；触发窗口、最小请求数、失败率和冷却期要按业务设。超时限制等待，重试处理临时失败，限流限制准入，熔断隔离持续故障，降级决定退化行为；这几个机制不能互相代替。

**完整口述：** 穿透是不存在，击穿是一个热点失效，雪崩是大量缓存或整个服务失效。当前med_rag缓存失败会绕过，但还没有回源保护；生产需短超时、限流和SingleFlight，并用熔断避免反复等故障节点。缓存写入和知识发布要管理版本。L2不缓存是故障隔离的一环，不能代替这些并发治理。

### 可使用的项目描述

- 构建/改造医疗科普RAG，采用MinerU完成2572篇本地文档解析、索引清洗与父子关联校验；采用BGE-M3双表示、Milvus加权融合、代表子块精排与父正文生成。

动词按实际贡献改。没有证据就不写“上线”“服务多少用户”“准确率提升多少”“消灭幻觉”“高QPS”“MCP/Agent已实现”。若写分数，附样本数、指标、裁判和实验范围。

### 推荐练习方式

1. 第一遍把流程讲顺：入口、每段输入输出、正常与异常分支。
2. 第二遍讲取舍：每个参数有什么依据、代价、替代与未验证项。
3. 第三遍讲证据：一个真实失败样例、修复、回归和未覆盖范围。
4. 模拟连续追问：实现→原理→参数→异常→替代→评估，每项至少说两层。
